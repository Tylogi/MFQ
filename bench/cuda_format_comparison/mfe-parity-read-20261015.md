# E8 奇偶位与只读码本候选

原型基线为普通 API 热轮 68.5292 tok/s 的组合。现已将 GU 候选接入生产路径，并保留此前的全部优化；新组合的 API 测量结果另列。不使用展开权重，局部计时不代表整模速度。

E8 第八个符号位原为 `popc(sign7)%2 XOR (sign_mode & (index>>7))`。因为 sign7 的第七位为零，可改成 `popc(sign7 | (index & ((sign_mode&1)<<7)))%2`，把索引的符号修正并入同一次 popcount。另对不变的 E8/D4 码本向量与 JSC Half 尺度 LUT 使用显式只读读取。权重记录、浮点点积次序、Half 舍入和现有符号展开不变。

成本预期：减少奇偶位修正指令，向编译器明确码本的只读属性；额外的 mask 活跃期、不同读取调度或生成代码布局可能抵消收益。未宣称当前普通全局读一定绕过 L1，也没有用静态指令数代替动态 stall 证据。

CPU 穷举全部 4096 个索引、128 个 sign7、两种模式，共 1,048,576 项等式检查通过。六层真实 S2-L、M1/3/8、共享/无共享、变化输入、重复及无效路由的 432 组最终输出、hidden 及量化值/scale 比较逐字节一致。调度沿用 `mfe_probe_schedule.h`，各图 384 节点/96 次 FFN，避免旧的 hidden 量化调度错误。

只测新候选，基线复用 `mfe-matched-s2l-20261015.json`，没有重跑原生产配置。服务在独立计时期间保持卸载。

历史匹配调度的含共享基线约 69.2～69.8 μs，控制样本有 1～2 μs 漂移。单侧候选显示小幅差值，联合结果没有呈现相加收益，当前不认定为稳定提升。原型、构建和全部结果保留，生产没有因此回退任何已启用优化。

## 生产接入及缓存准备优化

`mfe_ffn_parity_read.cu` 复用原有设备核，在独立编译单元中仅实例化两种标准 compact GU 掩码。`MFQ_MFE_PARITY_READ` 默认只对 M1 标准 GU 生效，显式设为 1 可用于兼容的多 token 标准 GU。Down、分组 GU 和单算子路径不变。日志 `mfe_parity_read_dispatch` 只在实际进入新启动器时输出。

同时加入 `MFQ_MFE_CACHE_PREPARE_SYNC`，默认开启。缓存准备以一次 CTA OR 检查是否有需要刷新的描述符：所有代数均已复制时跳过复制流程及其同步，映射写入后的同步则由紧接着的取消检查同步合并。缓存快照发布仍在全部分类和映射写入之后，CPU 不能提前修改借用地址。

生产验证已完成：

- 六层真实 S2-L、M1/2/6、共享/无共享、完整缓存/混合驻留/部分 GU 共 24 组；576 次变化输入图重放和初始结果逐字节一致。参考启动器显式关闭 GU 候选，候选显式开启，两个实际分派日志均出现。
- 同组 compute-sanitizer memcheck 97.42 秒、synccheck 16.02 秒，均为 `ERROR SUMMARY: 0 errors`。
- 完整缓存及部分 GU 的四种模式，在修改缓存地址并清零旧数据后共 24 项逐字节一致。
- 168 项普通窗口、84 项宽路由及部分 GU 串行窗口通过，包括缓存增长、淘汰、重复路由和无效路由取消。

检查日志为 `workspace/local-server/mfe-parity-read-production-*-20261015*.log` 和 `parity-gu-sync-pipeline-{normal,serial}-20261015.log`。构建清单 `cache-parity-gu-sync-api-build-20261015.json` 保存新二进制及相关源码 SHA256。整模对照只复用已有的 `speed-kv-route-fence-api-20261015.json`，不重测相同的旧配置。
