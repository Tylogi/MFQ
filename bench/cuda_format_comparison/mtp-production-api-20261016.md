当前按请求管理验证图与可回收专家缓存的版本，贪心热轮 **MTP 上限 3：77.44 tok/s、88.35% 接受率；上限 5：76.07 tok/s、83.13% 接受率；普通 decode：59.48 tok/s**。各为一次热轮，不是稳定均值。当前版本已用于本地 8090 服务。此前版本、随机采样及失败实验保留在下文，不能混作同一版本的重复样本。

## 按请求申请深度与共享空间（当前版本）

- 当前原生程序 SHA256：`0773eda6b0bcc2149e1695b3e283491869d9ce15677b5251778a9ec0a41e0c87`，构建目录 `workspace/build/mtp-depth-on-demand-v4-20261016`。
- 默认只预热深度 3 对应的最多 4 行验证。请求将 `mtp_max_draft_tokens` 提至 4/5 时才准备更深验证；降低上限会销毁旧验证图、释放相应工作区，再按新上限准备。相同上限且图有效时直接复用。
- 主专家数组地址和固定 RAM prefill 布局保持稳定。模型内存规划仍为最大可能验证工作区留出预算，但未启用部分由**可撤销的额外专家缓存**使用，不再空置；该缓存按实际空闲空间申请，保留 256 MiB 余量。主专家数组的物理预算为 14834257920 字节，额外专家缓存与 KV 空闲页缓存共同补充驻留；不能将主数组预算本身说成恢复到旧值。
- 增大深度、prefill 或 KV 增长需要空间时，先撤销这部分专家缓存的地址发布并等待搬运完成，再回收其分配。prefill 随后仍可借用原来的主专家工作区。这里没有实现任意主专家数组的零成本动态缩放。
- 非 KV 分配中的专家缓存单独记账，避免从 KV 占用中误扣。Graph 对专家地址的观察者绑定自身寿命，释放后不再保留旧元数据。

## 实现

- MTP 短窗口也按配置每 4 轮调整专家缓存，继续记录全部路由。Strata 本地源码 `references/strata`（`fb58e0dbc8399662c0e47c76578c6e878b14f6cf`）的 `src/program/generate.cpp` 默认 `adapt_every=4`。
- 单层草稿的已确认历史逐行更新 attention KV，最后一行执行完整 FFN/输出头。逐行执行保留标量数值路径；2/3/4 行调试对照相对标量完整草稿误差为 0。
- 草稿专家参与自适应驻留，拥有独立传输缓存；按 WDDM 实际共享内存预算尝试锁页。
- 草稿与验证 Graph 内生成 top-64，并一次传回打包结果。CPU 使用请求的 top-k、temperature、top-p 形成分布；惩罚采样、top-k 大于 64、完整 softmax 使用对应路径。
- 为尚未校准的较宽草稿保留实际测量机会；CUDA 的收益门槛为 3%，仍保留实测循环附加成本。
- 已预热的草稿历史 Graph 可与专家交换重叠；完整草稿继续等待专家状态。
- GDN 生成前缀状态时直接写检查点，省去额外状态复制。普通单 token 核使用原模板分支。
- 新请求首行可复用重置后的现有 Graph。KV 元数据一次原地重置，避免临时申请空闲槽位表。启动不再预热生产路径不用的多行完整草稿图。
- 采样 fallback 原有 1024-float 线程私有概率数组改为复用共享数组。加载日志中采样初始化的额外显存从 **396361728 字节（378 MiB）降为 0**，保留原专家预算。采样分支在专家定额前初始化，避免把这项成本留给首次请求。

全草稿专家常驻仅保留为显式诊断选项：本模型约需 2720407552 字节，实验中挤占主干缓存，整模反而变慢，因此默认使用分层缓存。
